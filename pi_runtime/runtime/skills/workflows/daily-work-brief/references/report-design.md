# 每日工作简报设计

## 1. 昨日小结

回答“昨天发生了什么、还有什么遗留”。可以按实际内容组织为：

- 完成或取得进展：有明确完成、回复、交付、会议结论等证据。
- 待回复或遗留：昨天提出、截至当前仍未解决的问题、@提及、承诺或错过的关键节点。
- 收到通知：重要但暂时不要求用户行动的公告、@all、报名或制度通知。

不要为了凑结构创建空分类；没有内容时简短说明未发现。

## 2. 今日规划

把跨来源证据转成今天可执行的有序清单。排序优先考虑“是否卡住他人”和“是否临近期限”：

- 🔴：正在阻塞他人、已经逾期、直接催办、必须立即回复。
- 🟡：今天到期、需要确认的错过会议、重要但尚未阻塞的跟进。
- 🟢：今天计划内会议、准备工作和正常推进事项。
- ⚪：低紧急度的信息检查或可选补充。

每项尽量说明动作、原因、涉及对象和时间，而不只是复述原消息。

## 3. 本周关注

列出当前时间之后未来 7 天内值得提前准备的会议、试用/报名/交付截止、承诺和项目节点。即使跨到下一自然周也可以列出，但必须显示具体日期和星期，避免“本周”产生歧义。

只保留需要用户记住、准备或主动确认的事项；普通日历占位不必全部抄录。

## 4. 备注

用于补充简报可信度和工作负荷判断，例如：

- 已实际查询但没有新增内容的来源。
- 因权限不足或接口失败而没有覆盖的来源。
- 今天日程密度、相对空闲时段或适合集中处理工作的时间。
- 存在冲突、重复安排或证据不完整的事项。

只有在确实查询过后才能声称“无新增”“没有待办”。

## 质量检查

输出前确认：

- 四个顶层模块齐全，模块内部没有为了格式而编造内容。
- 高优先事项确实有阻塞、期限或直接请求证据。
- “待回复”已经检查过后续会话状态。
- 已结束日程没有被无依据写成“已参加”。
- 没有把纯通知误写成行动项。
- 同一事项没有在多个模块重复堆叠；需要跨模块出现时，分别表达“昨日遗留”和“今日动作”。
- 日期、星期和时区正确。
- 没有内部 ID、Token、工具过程或原始 JSON。
