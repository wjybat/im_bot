# 办公知识图谱记忆库 — 结构与能力概述

> 面向汇报的概要版。完整 schema 与实现细节见 `pi_runtime/docs/memory.md`。

## 一、定位

本地 SQLite 知识库，把飞书办公消息加工成**可检索、可追溯、有状态**的知识图谱，支撑办公助理的即时问答与每日简报。核心设计：**图谱做索引和摘要（决定模型看什么），原始消息做证据（需要时展开）**。

## 二、四层结构（自底向上）

| 层 | 内容 | 作用 |
|---|---|---|
| 原始层 | 飞书 API 原始响应 | 支持规则升级后全量重放，不需重新拉取 |
| 消息层 | 规范化消息 + 会话（含修订版本） | "谁在什么时候说了什么" |
| 事实层 | 结构化结论（行动项/请求/承诺/决策/状态/期限/风险，共 8 类） | "世界上发生了什么事"，带生命周期 |
| 图谱层 | 实体（人/项目/系统/组织/文档/事件）+ 有类型边 | 关联检索与实体消歧 |

## 三、混合图模型

四类节点（消息、事实、实体、会话）通过统一边结构连接，全库为一张图：

**事实层结构（核心价值）**
- 每条事实绑定至少一条 primary 源消息（无证据不落库）
- 生命周期管理：新事实不删除旧的，通过 `SUPERSEDES` 边形成演化链——"方案待确认 → 方案已确认"的完整轨迹可回溯
- 结构化属性：类型、状态（open/done/…）、截止时间、指派人、置信度——支撑精确过滤（"本周截止的、还没完成的"）

**实体图结构（关联检索）**
- 实体带别名合并，解决同名/代号问题
- `ABOUT`/`ASSIGNED_TO` 边连接事实与实体；`AUTHORED_BY`/`REPLY_TO`/`TEMPORAL` 边构成消息间的结构骨架

## 四、检索：五路混合召回

单次查询并行走五条路由，排名融合（RRF）后按 token 预算装配：

1. 事实全文检索（结论命中）
2. 消息全文检索（原文命中）
3. 实体图路由（查询词 → 实体 → 一跳关联事实）
4. 结构化过滤（状态/期限/类型/与我相关）
5. 时序最近消息

**效果**：简报类问题命中压缩后的事实结论（数十字），而非全量原文（数千字），答案带证据指针可回查原文。

## 五、数据更新机制

- **后台预热**：固定时刻增量同步消息并批量抽取事实，日常维护热缓存
- **在线增量**：用户提问时按需补拉缺口、就地抽取（优先当前查询时段）
- **实时兜底**：高时效问题直接查飞书，结果自动回流入库
- **防污染**：助理与用户的对话本身不进入知识库，避免自我学习循环

## 六、当前规模与实证

- 消息 2,000+ 条（2026-08-28 起），事实 408 条，实体 617 个，边 3,079 条
- 检索路由实测：事实检索为主力命中来源，实体图路由占 <8%（关键词稀疏时发挥兜底价值）
- 单次抽取成本约 $0.001/chunk（低思考档），单轮预热 30 chunk 约 $0.03

## 七、价值判断与演进

- **已兑现**：事实层的压缩（多条消息 → 一条结论）、跨消息聚合（分散讨论 → 同一事实）、状态跟踪（待办的存活与完结）
- **预付的期权**：实体图当前贡献有限，但随数据跨月积累、问答从"待办清单"走向"关系问题"（如"两个项目都涉及的人"），其召回价值将持续放大；图层由抽取顺带产出，边际成本低
- **演进方向**：跨月事实压缩、向量语义检索、图社区聚类（README 已列为规划项）
