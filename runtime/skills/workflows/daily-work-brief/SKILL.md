# 每日工作简报

为当前授权用户生成以行动为导向的个人办公简报。不要把“待办”默认等同于飞书原生任务；需要综合能够说明用户已完成什么、正在卡什么、今天应做什么和近期要关注什么的办公证据。

开始前必须阅读 [references/report-design.md](references/report-design.md)。

## 时间范围

除非用户指定其他日期，以 `RUNTIME_CONTEXT_JSON` 中的 Asia/Shanghai 当前时间为准：

- 报告日：今天。
- 昨日：上一个自然日 00:00–23:59:59。
- 今日消息：今天 00:00–当前时间。
- 今日日程：覆盖今天整天，包括已经结束和尚未开始的日程。
- 近期关注：从当前时间开始至少覆盖未来 7 天；必要时延伸到明确存在的临近截止日期。

## 信息来源

所有个人办公信息必须来自当前授权账号。先加载并遵守 `lark-shared`，再按需要加载相应的集成 Skill。

聊天证据以“昨日 00:00 至当前”为一个连续报告范围，同时覆盖私聊和群聊，并尽可能更新到当前；由 Runtime 负责分页、增量同步和记忆更新。若覆盖仍不完整，在备注中说明，不要把部分结果写成完整结论。

调查时综合原始消息与带证据的当前事实：

- 昨日小结关注昨日发生的进展、决定、完成、取消和遗留事项；
- 今日规划关注至今仍有效的请求、承诺、待办、期限和阻塞，不要因为事项产生于昨日以前就遗漏；
- 本周关注结合未来期限、风险、承诺和日程安排；
- 高优先事项、状态冲突以及疑似已回复或已解决的内容必须核验最新原始证据。

事实记忆是派生索引，不是独立事实源。不得只看旧待办就认定仍未完成，应采用最新有效状态并保留可核验来源。

默认基础来源：

- `lark-im`：昨日和今日的私聊、群聊、@提及、问题、承诺、通知及后续状态。
- `lark-calendar`：昨日、今日和未来 7 天的日程、会议与 RSVP 状态。
- `lark-task`：未完成、逾期、今日到期或近期到期的飞书原生任务。

按相关性补充：

- `lark-mail`：需要回复、跟进或包含明确期限的邮件。
- `lark-approval`：等待用户处理或影响今天工作的审批。
- `lark-vc` / `lark-minutes` / `lark-note`：昨日会议的结果、待办或错过的信息。
- `lark-doc` / `lark-wiki` / `lark-drive`：消息或会议明确指向、且理解行动事项确实需要阅读的材料。

不要为了“覆盖更多”无目的遍历所有域。某来源没有权限时继续使用其他来源，并在备注中说明覆盖缺口。

## 调查原则

- 对消息汇总使用真实时间范围并充分分页；不要把“总结”“待办”等指令词当成消息搜索关键词。
- 用户与办公助手机器人的控制私聊不属于办公语料；即使其中复述了工作内容，也不能用作简报事实或补强证据。
- 判断“待回复”前，检查同一会话或话题中的后续消息，确认用户没有已经回答、事项没有被取消或解决。
- 优先展开并回源核验排序最高的 3–5 个行动候选；不要为了穷举所有低优先级候选逐个打开大量会话。其余内容可基于已有证据归入低优先级关注或在备注中说明未逐项展开。
- 如果后续证据表明事项已经完成、解决、取消或被新状态替代，不得继续按旧状态列为当前待办。
- 日程已经结束不等于用户实际参加；只有存在可靠证据时才写“已参加”，否则写“日程已结束”或“需确认是否遗漏信息”。
- 将同一事项在消息、日程、任务或邮件中的重复证据合并，避免重复列项。
- 区分事实与推断。证据不足但值得注意的内容放入“可能需要跟进”，不要写成确定待办。
- 每个重要结论尽量保留人类可核验的来源：会话/邮件/日程名称、发送人或发起人、日期时间。不得输出内部 ID。

## 输出要求

围绕四个模块组织：昨日小结、今日规划、本周关注、备注。模块内部的小标题、排序、措辞和详略可以根据当天信息自由调整，不需要机械复刻示例。

标题包含报告日期和星期。优先给行动结论，再给精炼证据。使用中文 Markdown，保持适合在飞书中快速浏览的长度。
